# Лабораторная работа: Сниффер и детектор снифферов

## Описание

Два независимых узла, соединённых в локальную сеть:

| Узел | Файл | Назначение |
|------|------|-----------|
| **Узел №1** | `node1_sniffer.py` | Переводит NIC в неразборчивый режим (promiscuous mode), захватывает и анализирует весь трафик сети |
| **Узел №2** | `node2_detector.py` | Обнаруживает работу сниффера в сети с помощью двух методов — ICMP и ARP |

Зависимостей нет: только **Python 3** и стандартная библиотека.

---

## Принцип работы

### Неразборчивый режим (promiscuous mode)

В обычном режиме NIC передаёт в ядро только фреймы, адресованные на MAC самого интерфейса и broadcast. В **promiscuous mode** все фреймы сети передаются в ядро без фильтрации.

Программа переключает режим через системный вызов `ioctl` с флагом `IFF_PROMISC`.

### Обнаружение сниффера

Оба метода основаны на одном принципе:

> Отправить Ethernet-фрейм с **поддельным (несуществующим) unicast MAC-адресом** назначения.
>
> - **Нормальный NIC**: аппаратный фильтр отбрасывает фрейм (MAC не совпадает) → хост не отвечает.  
> - **NIC в promiscuous mode**: все фреймы передаются ядру → ядро обрабатывает IP/ARP-пакет → хост отвечает → **сниффер обнаружен**.

#### Метод ICMP

Отправляем ICMP Echo Request с поддельным `dst MAC`. Если пришёл Echo Reply — цель в promiscuous mode.

#### Метод ARP

Отправляем ARP Request с поддельным unicast `dst MAC` (не broadcast). Если пришёл ARP Reply — цель в promiscuous mode.

## Требования

- **ОС**: ALT Linux (или любой Linux с Python 3.10+)
- **Python**: 3.10 или новее (используется `str | None` в аннотациях)
- **Права**: оба скрипта требуют `root` (raw sockets + ioctl)
- **Сеть**: Узлы №1 и №2 должны быть в одной L2-сети (один коммутатор/патч-корд)

## Настройка сети

### Физическое / виртуальное подключение

Соедините два компьютера (или две виртуальные машины) в одну локальную сеть.

### Назначение IP-адресов

**Узел №1:**
```bash
sudo ip addr add 192.168.100.1/24 dev eth0
sudo ip link set eth0 up
```

**Узел №2:**
```bash
sudo ip addr add 192.168.100.2/24 dev eth0
sudo ip link set eth0 up
```

Проверка связи:
```bash
ping 192.168.100.1   # с Узла №2
```

> Замените `eth0` на актуальное имя интерфейса (`ip link show`).

## Запуск

### Узел №1 — сниффер

```bash
# Узнать имя интерфейса
sudo python3 node1_sniffer.py --list

# Запустить захват (Ctrl+C для остановки)
sudo python3 node1_sniffer.py -i eth0

# Захватить ровно 50 пакетов и выйти
sudo python3 node1_sniffer.py -i eth0 -n 50
```

#### Опции

| Ключ | Описание | По умолчанию |
|------|----------|-------------|
| `-i`, `--interface` | Сетевой интерфейс | `eth0` |
| `-n`, `--count` | Лимит пакетов (0 = без лимита) | `0` |
| `-w FILE`, `--write FILE` | Сохранить пакеты в PCAP-файл | — |
| `-v`, `--verbose` | Подробный вывод с hex-дампом payload | выкл. |
| `--list` | Показать доступные интерфейсы | — |

#### Сохранение в PCAP (формат Wireshark)

```bash
# Захватить трафик и сохранить в файл
sudo python3 node1_sniffer.py -i eth0 -w capture.pcap

# Захватить 200 пакетов с подробным выводом и сохранить
sudo python3 node1_sniffer.py -i eth0 -w capture.pcap -n 200 -v

# Открыть результат в Wireshark
wireshark capture.pcap

# Или проанализировать через tcpdump
tcpdump -r capture.pcap
```

PCAP — стандартный бинарный формат (`libpcap`). Файл содержит глобальный заголовок и последовательность записей вида `(timestamp, длина, сырые байты фрейма)`. Wireshark откроет его без каких-либо плагинов.

#### Флаг `-v` — hex-дамп payload

```
[12:34:02.001] #   3  ICMP  192.168.100.2 → 192.168.100.1  [Echo Request]  TTL=64  len=84
         MAC: aa:bb:cc:dd:ee:ff → 00:de:ad:be:ef:00
         0000  53 4e 49 46 46 45 52 5f  44 45 54 45 43 54 5f 49  SNIFFER_DETECT_I
         0010  43 4d 50                                           CMP
```

### Узел №2 — детектор

```bash
# Базовая проверка
sudo python3 node2_detector.py 192.168.100.1 -i eth0

# Три повторения теста (повышает достоверность)
sudo python3 node2_detector.py 192.168.100.1 -i eth0 -n 3
```

#### Опции

| Ключ | Описание | По умолчанию |
|------|----------|-------------|
| `target_ip` | IP проверяемого хоста | (обязательный) |
| `-i`, `--interface` | Сетевой интерфейс | `eth0` |
| `-n`, `--repeat` | Число повторений каждого теста | `1` |

#### Коды завершения

| Код | Значение |
|-----|---------|
| `0` | Сниффер не обнаружен |
| `1` | Сниффер обнаружен |

## Порядок демонстрации

1. Соединить Узлы №1 и №2 в локальную сеть, назначить IP-адреса.
2. **На Узле №1** запустить сниффер:
   ```bash
   sudo python3 node1_sniffer.py -i eth0
   ```
3. **На Узле №2** запустить детектор:
   ```bash
   sudo python3 node2_detector.py 192.168.100.1 -i eth0
   ```
4. Убедиться, что:
   - Узел №2 сообщает о **обнаружении сниффера**.
   - Узел №1 перехватывает пакеты детектора (виден поддельный MAC `00:de:ad:be:ef:00`).
5. Остановить сниффер (Ctrl+C на Узле №1). Запустить детектор снова — теперь он должен сообщить, что сниффер **не обнаружен**.
